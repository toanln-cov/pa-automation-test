Tổng quan
  • Điền template Excel, upload ở trang Configure. Tool áp dụng từng dòng lên các firewall Palo Alto trong cột Device-ip qua PAN-OS REST API.
  • Tool hỗ trợ:
    • Tạo mới: tag, address object, address group (tĩnh), service object, service group, security rule, NAT rule.
    • Sửa: tag, address object, address group, service object, service group, security rule, NAT rule.
    • Không hỗ trợ xóa: hành động xóa có thể gây ảnh hưởng lớn, nên khuyến nghị chủ động xóa thủ công trên firewall.
  • Xem các job đang chạy và đã chạy xong trong Job history.
  • Job cấu hình chỉ ghi vào candidate config và không commit trên firewall, để giảm thiểu tối đa ảnh hưởng. Admin cần review, rồi thực hiện commit check và commit ở tab Commit riêng.
  • Tool chỉ chạy một job tại một thời điểm.
  • Không hỗ trợ Panorama: tool không cấu hình Panorama và không hỗ trợ firewall do Panorama quản lý, để tránh xung đột cấu hình.
  • Phiên bản PAN-OS: chỉ các phiên bản còn được hỗ trợ trên portal API của Palo Alto (11.1 trở lên, 10.2, 10.1).

Thứ tự thực thi
  1. Kiểm tra file — tên sheet và tên cột phải đúng như template, nếu không file bị từ chối.
  2. Đăng nhập — mỗi firewall lấy một API key dùng cho cả job. Những Firewall sai mật khẩu hoặc không kết nối được thì bỏ qua, các dòng cấu hình cho firewall khác vẫn chạy. Nếu mọi firewall đều lỗi → bị từ chối trước khi tạo job).
  3. Lần lượt với từng firewall được deploy theo thứ tự: Lấy firewall version để mapping API version → Config lock → Backup cấu hình (snapshot Auto-<ngày giờ>.xml) → Cấu hình từng dòng từ file import → Gỡ config lock → Tiếp tục cycle với firewall tiếp theo.
  4. Thứ tự dòng cấu hình: Tool sẽ thực hiện tuần tự từ trên xuống dưới
  5. Luôn unlock config ở bước cuối, kể cả deploy lỗi khi có lỗi.

Config lock: trong lúc job chạy, tool khóa cấu hình trên firewall để admin khác không sửa cùng lúc, xong firewall đó thì tự gỡ khóa. Firewall đang bị admin khác khóa → tool không ghi gì vào firewall đó và báo trong kết quả job.

Template & các sheet

Sử dụng 1 file template duy nhất.

template.xlsx
Thứ tự chạySheet (luôn theo thứ tự này, bất kể thứ tự sheet trong file)
1. Các sheet addadd_tag → add_address_object → add_address_group → add_service_object → add_service_group → add_security_rule → add_nat_rule
2. Các sheet editedit_tag → edit_address_object → edit_address_group → edit_service_object → edit_service_group → edit_security_rule → edit_nat_rule

Ghi chú:

  • File import chỉ chứa những sheet cần dùng. Sheet nào không cần thì xóa khỏi file (để lại sheet trống → cả file bị từ chối). Ví dụ chỉ thêm address và gắn vào rule có sẵn → file chỉ có add_address_object và edit_security_rule.
  • Trong một sheet, Tool sẽ cấu hình theo thứ tự từng dòng từ trên xuống theo người dùng sắp xếp.
  • Hỗ trợ cấu hình nhiều vsys trên cùng Firewall (bao gồm cả vsys shared).
  • Màu header: đỏ = bắt buộc, vàng = bắt buộc tùy trường hợp, xanh = tùy chọn.
  • Dòng 2 mỗi sheet là dòng ví dụ: thay hoặc xóa trước khi upload.
  • Chỉ nhập giá trị, không dùng công thức Excel. Ô có ký tự vô hình hoặc lỗi Excel bị từ chối kèm vị trí ô.
  • Danh sách cách nhau dấu phẩy, không thừa dấu phẩy, không lặp tên.
  • Sheet edit: Tool đọc cấu hình hiện tại trên firewall, chỉ thay những gì điền trong file, các phần khác giữ nguyên. Không đổi tên, không chuyển vsys.
  • Sheet edit object (edit_tag, edit_address_object, edit_service_object): Tool thực hiện thay đổi toàn bộ giá trị thành giá trị mới (không sử dụng Edit-*-Mode), ô trống = giữ nguyên, none = xóa.
  • Sheet edit rule và group: mỗi cột có cột chế độ Edit-<Cột>-mode: add (thêm vào danh sách), remove (bỏ khỏi danh sách), replace (thay giá trị / cả danh sách, none = xóa), remain hoặc trống (giữ nguyên). Chi tiết ở từng sheet.

Shared (sheet object, group, service, tag): ghi Vsys = shared để đặt object vào shared, mọi vsys của firewall đều dùng được. Lưu ý:

  • Group / tag của object ở shared chỉ dùng được object / tag ở shared.
  • Rule luôn nằm trong vsys: shared ở sheet rule → file bị từ chối.
  • Không tạo được object ở vsys trùng tên object ở shared (... already exists in shared); trùng giá trị → Warning: Duplicate Value with X (shared).
  • Sheet edit sửa được entry ở shared (Vsys = shared).

Dry-run

Dry-run chỉ lấy thông tin từ firewall, không ghi gì, và báo trước kết quả của từng dòng: CAN CREATE / CAN EDIT / CAN MOVE hoặc lỗi. Dry-run kiểm tra giá trị từ file cấu hình từ admin có đúng định dạng không, có khả thi khi cấu hình thực tế vào Firewall không.

Dry-run cover phần lớn các trường hợp trước khi Install, nhưng không phải 100% (ví dụ interface, source user không được kiểm tra).

Cho nên khuyến nghị là luôn chạy Dry-run trước để giảm thiểu lỗi input. Từ đó admin có thể xem lại kết quả, rồi chạy Install.

Stop duplicated

Stop duplicated (chỉ có ở Install) dùng để tránh tạo cấu hình tạo thêm một object/rule mới có trùng giá trị với object/rule cũ đã có trên firewall. Mục đích của tính năng này chỉ để bớt tạo các object/rule thừa.

  • Tick: Dòng trùng giá trị bị bỏ qua, không tạo. Các dòng khác vẫn chạy bình thường.
  • Không tick: dòng trùng vẫn được tạo, kết quả kèm cảnh báo trùng.

Khi sử dụng Dry-run, Tool luôn kiểm tra trùng giá trị này để cảnh báo các object/rule bị có cùng giá trị với giá trị định tạo.

Commit check & Commit

Mục đích: job cấu hình bằng template chỉ ghi vào candidate config, không tự commit. Sau khi job chạy xong, quản trị viên xem lại kết quả và cấu hình trên firewall, rồi tự quyết định chạy commit check hoặc commit. Như vậy mọi thay đổi chỉ có hiệu lực khi có quản trị viên kiểm soát và chấp thuận, giảm rủi ro áp dụng nhầm cấu hình.

Thực hiện ở trang Commit, tách riêng khỏi template. Nhập IP firewall (IP đơn, dải a-b, CIDR), username và password.

  • Commit check: chỉ kiểm tra (validate), không áp dụng gì. Chạy trước và xem kết quả từng firewall.
  • Commit: áp dụng candidate config.
  • Phạm vi, cho cả Commit check và Commit (bắt buộc chọn, không có mặc định): chỉ thay đổi của user này (partial) hoặc toàn bộ thay đổi.
  • Tối đa 5 firewall song song. Firewall không có thay đổi chờ commit sẽ được bỏ qua.
